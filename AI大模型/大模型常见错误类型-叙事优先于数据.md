# 大模型常见错误类型：叙事优先于数据

> 记录时间：2026-05-30
> 场景：大盘回顾报告写作，妙想数据驱动的量化分析

## 错误表现

在分析本周（05/25-05/29）大盘数据时，观察到周五成交额1.532万亿全周最高，且当日下跌-0.73%，于是写出结论：

> **"周五成交额达1.532万亿为全周最高，但跌幅也最大，日内抛压集中释放"**

实际上涨跌幅最高的日期是周三（05/27，-1.25%），周五跌幅（-0.73%）仅为第二。这句话中的"跌幅也最大"是事实错误。

## 错误链条

```
观察到"周五成交额最高" 
  → 自动激活"放量下跌=资金出逃"叙事模板
    → 默认"成交额最高=跌幅也应该最大"
      → 写进结论，没有做交叉验证
```

## 根因：叙事驱动而非数据驱动

核心问题不是数据不足，而是**在数据之前已经形成了叙事预期**：

1. **情景锚定**：脑子里先有"放量下跌=抛压集中释放"的故事，然后找数据去匹配这个框
2. **注意力偏差**：周五是一周的最后一个交易日，又是"量最大+收跌"，在数据回顾中天然最突出，容易高估其分析权重
3. **维度混淆**："成交额最高"和"跌幅最大"是两个独立的比较维度，但被错误地关联为因果关系——成交额最高不一定等于跌幅最大，也可能是多空分歧加大、换手率上升，甚至是有资金主动接盘

## 数据验证

正确的五天平铺对比：

| 日期 | 成交额 | 涨跌幅 |
|------|--------|--------|
| 周一 | 1.446万亿 | +0.96% |
| 周二 | 1.462万亿 | -0.17% |
| 周三 | 1.473万亿 | **-1.25%** ← 这才是最大跌幅 |
| 周四 | 1.361万亿 | +0.12% |
| 周五 | **1.532万亿** | -0.73% ← 跌幅仅第二 |

平铺后一目了然：周三才是真正的"放量杀跌日"；周五天量成交+跌幅减半，逻辑上反而可能是有资金在低位接盘。

## 防范方法

**任何含"最"字的判断落笔前，必须经过三步验证：**

1. **列出全部比较对象的具体数值**（不能凭印象写）
2. **确认排名正确**
3. **确认比较维度没有混淆**（成交额、涨跌幅、换手率是不同的维度，不能混为一谈）

更深层的防范：**写有数据的结论之前，先把相关维度的数据摊平在同一张表里看一眼**，而不是依赖短期记忆去写。

## 同类错误模式

| 模式 | 典型案例 | 防范 |
|------|---------|------|
| 叙事优先 | 先有"放量=出逃"故事，再找数据匹配 | 倒过来：先看数据，再形成叙事 |
| 叙事覆盖反例 | "科技全线溃退"→实际通信+5.57%、电子-0.35%，通信才是最大亮点 | 结论前先扫一遍所有子项，有反例必须修正表述 |
| 注意力偏差 | 最后一天的数据权重最大 | 所有交易日均衡对待，按时间平铺 |
| 维度混淆 | "量最大=跌幅最大"或"放量下跌居多"→忽略沪深300、创业板指放量上涨 | 每次只讨论一个维度，分列对比 |
| 单一信号过度解读 | 一个数据点支撑一个判断 | 至少两个独立数据源交叉验证 |
| 惯性笔误与编号疏忽 | 分析列写"缩量"（事实错误）、序号跳跃重复 | 结论类文字完成后再通读一遍 |
| **排序逻辑错误** | 表格声称按涨幅降序排列，但煤炭+6.66%排在公用事业+6.58%之后，"本周最强"标在第二强头上 | 排序表格必须数据驱动——先对所有数值排序，再格式化输出，不能逐行凭印象排 |
| **计数错误** | "仅5个行业上涨"→实际6个，漏数了银行(+0.94%) | 计数必须逐行清点落表，不能凭"印象流"估算 |
| **过度因果推断（虚假确信）** | "放量不跌→说明有资金承接"未考虑卖盘衰竭、空头回补等替代解释 | 统计关联≠因果，对同一现象至少列出2-3种可能解释，再指出哪种最可能及如何验证 |
| **技术指标幻觉** | 布林线数值精确到个位数但未注明参数（20日±2σ），无法验证 | 技术指标必须注明参数，且声明来源为数据商计算而非自主计算 |
| **用词量级不匹配** | "暴跌-2.20%"（A股周度2.2%属中等波动）、"牛市"（0.97%涨幅） | 情绪词必须对标数据量级：周度>3%可用"大跌"，>5%可用"暴跌" |

## 经验教训

这个错误的成本很低——被用户发现后当场修正即可。但同类错误在更复杂的分析场景里（如交叉验证多条逻辑链时），可能更难被发现。**在数据分析中，叙事应该是数据的结果，而不是数据的原因。**

### LLM签名错误：排序和计数

排序错误和计数错误是最具"LLM签名"特征的问题——人类分析师几乎不可能在表格中将6.66%排在6.58%之后还标注"最强"，也不会把6个正数数成5个。但大模型由于自回归生成的机制限制，这类错误反而高频出现：

- **排序错误**：模型逐行生成而非先排序后格式化。如果原始数据中公用事业出现在煤炭之前，模型就照这个顺序输出"1、2"，不检查数值大小
- **计数错误**：模型缺乏精确计数能力，在生成过程中对自身产出做"心算统计"时极易出错，且一旦生成错误数字，会在后文反复引用固化，形成自我强化的系统性错误

### 系统性风险图谱

| 错误类型 | 严重程度 | 根因 | 检测难度 |
|---------|---------|------|---------|
| 排序逻辑错误 | 🔴 高 | 逐行生成而非先排序 | 低（直接比对即可发现） |
| 计数错误 | 🔴 高 | 缺乏精确计数能力 | 低（逐行清点即可发现） |
| 数据完整性矛盾 | 🟡 中 | 输出遗漏或循环推导 | 中（需交叉验证逻辑） |
| 过度解读/虚假确信 | 🟡 中 | 叙事偏好替代因果论证 | 高（需要领域知识判断） |
| 用词情绪化 | 🟡 中 | 修辞优化本能 | 中（需对比数据量级） |
| 技术指标幻觉 | 🔴 高 | 无法真正执行数值计算 | 高（需独立重算验证） |
| 环比计算微偏 | 🟢 低 | 浮点精度或中间值四舍五入 | 低（逐项验算即可） |

### 两类隐蔽性最高的错误

- **虚假确信的因果推断**：将统计相关性直接解释为因果，且只选了最有叙事吸引力的一种解释，忽视了卖盘衰竭、空头回补等替代假说
- **技术指标幻觉**：生成看似精确的数值（布林线中轨4121），却不注明参数来源，读者若据此做交易决策风险极大
